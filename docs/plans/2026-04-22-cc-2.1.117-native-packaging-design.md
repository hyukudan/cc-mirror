# Migrate cc-mirror to Claude Code 2.1.117 native-binary packaging

**Date**: 2026-04-22
**Status**: Approved, pending implementation plan

## Context

Claude Code 2.1.113+ ships as platform-specific native binaries pulled via
`optionalDependencies` + a `postinstall install.cjs` that copies the correct
binary over `bin/claude.exe`. The main package no longer contains `cli.js`,
which cc-mirror assumes throughout (`resolveNpmCliPath`, `CliPatch`,
`TeamModeStep` legacy `sU` patch, wrapper `node cli.js`, `variant.json.binaryPath`).

All four existing mirrors (`alibaba`, `claudefase` × 2 users) are on 2.1.112,
the last version with the legacy layout. Latest on npm is **2.1.117**.

## Goal

Move cc-mirror all-in to the native-binary layout. Drop legacy `cli.js`
support entirely. Migrate all existing variants to 2.1.117 via `update`.

## Non-goals

- Preserve legacy (≤2.1.112) install path as a fallback
- Restore theming for native builds (tweakcc auto-skip is acceptable)
- Change provider/brand configuration model

## Architecture

Post-migration pipeline (unchanged step order):

```
PrepareDirectories → InstallNpm(+postinstall fallback) → WriteConfig →
BrandTheme → TeamMode(config only) → Tweakcc(auto-skip) →
Wrapper(exec binary) → ShellEnv → SkillInstall → Finalize
```

### Changes

| Module | Change |
|---|---|
| `src/core/constants.ts` | `DEFAULT_NPM_VERSION = '2.1.117'` |
| `src/core/install.ts` | Rename `resolveNpmCliPath` → `resolveClaudeBinaryPath`. Return `bin/claude.exe` on Windows, `bin/claude` on POSIX. Postinstall fallback: if binary missing after install, run `node install.cjs` in the package dir. |
| `src/core/variant-builder/steps/cli-patch.ts` | **Delete step** and remove from pipeline |
| `src/core/variant-builder/steps/team-mode.ts` | Remove `sU` patch and cli.js detection. Keep config/prompts/toolset setup. |
| `src/core/wrapper.ts` | Exec native binary directly; drop `node` invocation |
| `src/core/variant.ts` (variant.json) | `binaryPath` points to native binary |
| `src/core/variant-builder/steps/brand-theme.ts` | No functional change — writes `tweakcc/config.json` regardless |
| `test/helpers/withFakeNpm.ts` | Fake package layout: `bin/claude.exe` + `install.cjs` (drop `cli.js`) |

### Postinstall handling

pnpm v10 blocks postinstall by default. Fix is package-manager-agnostic:

```
after install:
  if !exists(binaryPath):
    cwd = npmDir/node_modules/@anthropic-ai/claude-code
    if exists(cwd/install.cjs):
      run: node install.cjs
    if still !exists(binaryPath):
      throw: "postinstall ran but binary not produced — check optionalDependencies for your platform"
```

### Migration

Running `cc-mirror update <name>` on existing 2.1.112 variants:

1. Install step pulls 2.1.117, runs postinstall (or falls back)
2. `CliPatch` step no longer exists, skipped naturally
3. `TeamModeStep` writes config but no `sU` patch applied
4. `Wrapper` regenerates with native-exec form
5. `variant.json.binaryPath` updated to point at native binary

No manual action needed. After cc-mirror is rebuilt, update the 4 known variants:

```
npm run dev -- update alibaba
npm run dev -- update claudefase
# For preparaoposiciones, same command as that user with appropriate HOME
```

## Risks

- **Platform native package missing**: if `optionalDependencies` install failed
  silently (e.g. musl vs glibc mismatch), `install.cjs` runs but produces no
  binary. The fallback surfaces this as a clear error instead of mysterious
  "cli.js not found".
- **Binary permissions**: `install.cjs` sets exec bit; verify our fallback
  invocation preserves it.
- **pnpm future-proofing**: if a later pnpm relaxes script blocking, the
  fallback becomes a no-op — harmless.
- **Wrapper env-passthrough**: current wrapper sets `ANTHROPIC_BASE_URL`,
  `ANTHROPIC_API_KEY`, `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_TEAM_NAME` before
  exec. Native binary respects these the same way as the JS CLI (verified
  against Anthropic's native launcher design).

## Rollback

If 2.1.117 proves broken in the field: revert the cc-mirror commit and pin
`DEFAULT_NPM_VERSION` back to `2.1.112` on a hotfix branch. Existing variants
can be downgraded with `update --npm-version 2.1.112` assuming the legacy
code path is restored.
